# Retraining the A8 virtual stains on the 2026-08-12 acquisition (TOMM20 panel)

*Written 2026-10-31, before the data had been surveyed. Steps 1–2 are the survey and the one
config edit it drives; everything after is the existing pipeline with the new config. The
export: `Z:\Blair_Main\2026\081226\260812_Blair_Sperm_A8\260812\B5-All Primary 1_002.zip`,
one well ("All Primary", plate B5), full primary panel, TOMM20 where July had CD45.*

## What is different from July, and what the code now does about it

| July design | 2026-08-12 | handled by |
|---|---|---|
| nine wells named `A3-3S`, `B3-3P`, `C3-3SP` (type × replicate) | one well, `B5-All Primary 1_002` | `[classes.samples]` in the config names the sample and its class letter |
| two stained replicates: train on 2, test on 3 | one acquisition | `split_halves = true`: first half of the events → class `2M` (train), second half → `3M` (held out); the trainer's `--train 2 --test 3` is unchanged |
| spillover estimated from the pure S and P wells | no pure wells | `[spillover] source = "identity"`, or the path of the July cache's `spillover.json` if fluorophores and filters are unchanged |
| images in `<stem>_images\` folders | the instrument's `<stem>.zip` | the reader reads TIFFs straight from the zip; no extraction |
| LDHC/AKAP4, CD45, ACRV1 | LDHC/AKAP4, TOMM20, ACRV1 (to confirm) | `[stains]` in the config; TOMM20 already has a marker config, colour and compartment (midpiece) from the ImageStream |

What is lost with one mixed well: the well-based validation (pure wells as population labels,
the carried-over-sperm story) and the AUC of a predicted marker between wells. What remains:
event and pixel r, IoU against the measured stains (raw or denoised), the measured-side
clustering as truth, and expert annotation. The train / test split is by acquisition time
within one run, so a reviewer will ask about leakage: the two halves share staining, gain and
background, which the July replicate split did not. Say so.

## Steps, on the server

1. **Survey the export** (read-only, a minute or two):
   ```
   python scripts\survey_a8_export.py "Z:\Blair_Main\2026\081226\260812_Blair_Sperm_A8\260812" --out survey_260812.txt
   ```
   Read section [2] (FCS labels: which fluorophore carries which antibody) and [3] (TIFF page
   names and count). The checklist in [4] lists anything else that moved.

2. **Set the stains in `configs\instruments\a8_260812.toml`** from the survey: marker → page index
   in the 6-page TIFF (0 LightLoss, 1 FSC, 2 SSC, 3–5 the fluorescence filters in the order the
   survey prints). The file ships with LDHC/AKAP4 = 3, TOMM20 = 4, ACRV1 = 5, i.e. July's filters
   with TOMM20 on PE. If a fourth fluorescence page appears, or DAPI is imaged, stop: the unmixing
   triangle and the three-head model need a design decision first. If the fluorophores are
   unchanged, `[spillover] source` can point at the July cache (`data\server_cache\a8_roles`) to
   reuse its matrix; otherwise leave `identity`.

3. **Prepare, train, evaluate** in one go (prepare ~15 min for 20,000 events, train ~2–3 h at
   40 epochs, figures ~15 min); the suffix keeps the July run intact:
   ```
   .\scripts\server_stems.ps1 -A8Run "Z:\Blair_Main\2026\081226\260812_Blair_Sperm_A8\260812" -A8Config configs\instruments\a8_260812.toml -Suffix _260812 -A8Well M
   ```
   Outputs: cache `data\server_cache\a8_roles_260812`, run `runs\srv_a8_stems_260812`, figures
   `figures\srv_a8_260812_*`, and the usual results zip. `-DenoiseTargets smooth` can be added to
   train on denoised measured stains, or the scoring commands below take `--denoise-measured`.
   The ablation (light loss / FSC / SSC subsets) runs as part of it.

4. **Score against denoised measured stains** (what the abstract now quotes):
   ```
   python -m sperm_fluorescence accuracy runs\srv_a8_stems_260812 --cache data\server_cache\a8_roles_260812 --test 3 --title "A8 2026-08-12, held-out half" --sample 60000 --denoise-measured smooth --out figures\srv_a8_260812_accuracy_denoised
   python -m sperm_fluorescence masks runs\srv_a8_stems_260812 --cache data\server_cache\a8_roles_260812 --test 3 --limit 20000 --calib 400 --denoise-measured smooth
   python analysis\metrics_table.py runs\srv_a8_stems_260812 --accuracy figures\srv_a8_260812_accuracy_denoised\summary.json --denoise smooth --denoised-only --label "A8 2026-08-12"
   python -m sperm_fluorescence panel runs\srv_a8_stems_260812 --cache data\server_cache\a8_roles_260812 --test 3 --rows best:5 --main M --stained "LDHC/AKAP4,ACRV1" --size 56 --um-per-px 0.333 --approx-scale --range sample --denoise-measured smooth --marker-order ACRV1,TOMM20,LDHC/AKAP4 --out figures\srv_a8_260812_panel.png
   ```

5. **Virtual stains, features, clustering** on the held-out half: `server_populations.ps1` is
   written for the July cache and run names, so run its stages by hand with the new names
   (the commands are the same ones it contains):
   ```
   python -m sperm_fluorescence predict runs\srv_a8_stems_260812 --cache data\server_cache\a8_roles_260812 --classes 3M --tta --out data\server_cache\a8_vstain_260812
   python -m sperm_fluorescence features data\server_cache\a8_vstain_260812 --out data\server_cache\a8_vstain_260812\features.csv
   python -m sperm_fluorescence populate data\server_cache\a8_vstain_260812\features.csv --set all --k 2 --no-gates --store data\server_cache\a8_vstain_260812 --gallery-n 8 --out runs\pop_srv_a8_260812_feat_k2
   python -m sperm_fluorescence populate data\server_cache\a8_vstain_260812\features.csv --set all --k 3 --no-gates --store data\server_cache\a8_vstain_260812 --gallery-n 8 --out runs\pop_srv_a8_260812_feat_k3
   python analysis\confusion_matrix.py runs\pop_srv_a8_260812_feat_k2 --names sperm leukocyte --out figures\srv_a8_260812_pop_feat_k2_confusion.png
   python analysis\cluster_grid.py runs\pop_srv_a8_260812_feat_k2 runs\pop_srv_a8_260812_feat_k3 --store data\server_cache\a8_vstain_260812 --views stains ssc --out figures\srv_a8_260812_pop_grid_k2_k3.png
   ```
   With TOMM20 in place of CD45 the k = 2 split is no longer guaranteed to be sperm versus
   leukocyte: TOMM20 marks every mitochondrion, so leukocytes and sperm midpieces both carry it,
   and the leukocyte-specific geometry (a thick round CD45 body) is gone from the feature table.
   Expect the first split to be driven by the light-loss / scatter shape and by the LDHC tail;
   read the galleries before naming the clusters. The confusion matrix's `--names` must follow
   what the galleries show, by cluster id (`"0=..." "1=..."`).

## Before any of this: the CD45 / TOMM20 question on the July data

The July A8 panel is labelled CD45 on PE by the instrument and behaves as a leukocyte stain in
sixty thousand cells; the staining record is still being confirmed. This rerun does not depend
on it: the new panel's labels come from the new FCS files and the survey, and the 2026-08-12
marker is TOMM20 by the mentor's account. If the July channel also turns out to be TOMM20, the
July results are relabelled with `scripts/relabel_markers.py` and the July midpiece absence
becomes a finding to explain, not a label to hide.
