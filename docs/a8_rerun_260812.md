110,000–188,000 events each, 271 FCS parameters, the same six TIFF pages as July (LightLoss, FSC,

Panel, from the FCS labels: **LDHC** on Alexa Fluor 488 (no AKAP4 this time), **TOMM20** on PE,
**ACRV-1** on PerCP-eFluor 710, DAPI as a scalar only. Images (20,000 per well, the capture cap,
out of ~125,000 events) exist as `<well>_images\` folders for A5 and B5 only; the instrument's
`.zip` files hold the recording metadata, not images, and the other 18 wells' images are still
inside their 1.5 GB `.cvw` recordings.

This is a better design than July for the virtual stain and a worse one for the sorting story:
columns 2–4 are fluorescence-minus-one controls (one antibody omitted each), which give a clean
spillover estimate and a per-marker negative control once their images are exported; the
dilution rows show how signal-to-noise moves with antibody concentration. There are no PBMC
wells, so the sperm-versus-leukocyte clustering cannot be validated here, only whatever
leukocytes the ejaculate itself contains.

## What is different from July, and what the code now does about it

| July design | 2026-08-12 | handled by |
|---|---|---|
| wells named `A3-3S`, `B3-3P`, `C3-3SP` (type × replicate) | `A5-All Primary 1_001`, `B5-All Primary 1_002` | `[classes.samples]` in `configs/instruments/a8_260812.toml` names each stem and its class |
| two stained replicates: train on 2, test on 3 | two "all primary" acquisitions at 1:400 (A5) and 1:800 (B5) | A5 → class `2M` (train), B5 → class `3M` (held out); the trainer's `--train 2 --test 3` is unchanged. Separate acquisitions, so no within-run leakage; the dilution differs, which Pearson r and relative-threshold IoU do not see but absolute intensity does |
| spillover estimated from the pure S and P wells | no S / P wells | `[spillover] source = "matrix"` with July's coefficients (same fluorophores and filters); swap to an estimate from the FMO wells once their images are exported |
| LDHC/AKAP4, CD45, ACRV1 | LDHC, TOMM20, ACRV1 | `[stains]`; the marker name `LDHC` now has a config, colour, compartment (flagellum) and gallery entry alongside `LDHC/AKAP4`; TOMM20 had them from the ImageStream |
| images in `<stem>_images\` | the same, for A5 and B5 | nothing to do; the reader also reads TIFFs straight from a zip if an export ever ships them that way |

What is lost: the well-based validation and the leukocyte AUC. What remains: event and pixel r,
IoU against the measured stains (raw or denoised), the measured-side clustering, the FMO wells as
true negative controls when their images arrive, and expert annotation.

## Steps, on the server

1. **Survey** — done (`survey_260812.txt`); rerun it after exporting more wells' images so the
   checklist sees them.

2. **Config** — `configs\instruments\a8_260812.toml` is set from the survey (stains, the A5 / B5
   classes, July's spillover matrix). Nothing to edit unless more wells are exported: then add
   them under `[classes.samples]` (e.g. `"A3-No TOMM20 1_400" = "2N"` for a negative control that
   should train alongside, or leave controls out of training and only predict on them).

3. **Prepare, train, evaluate** in one go (prepare ~15 min for 20,000 events, train ~2–3 h at
   40 epochs, figures ~15 min); the suffix keeps the July run intact:
   ```
   .\scripts\server_stems.ps1 -A8Run "Z:\Blair_Main\2026\081226\260812_Blair_Sperm_A8\260812" -A8Config configs\instruments\a8_260812.toml -Suffix _260812 -A8Well M
   ```
   Outputs: cache `data\server_cache\a8_roles_260812`, run `runs\srv_a8_stems_260812`, figures
   `figures\srv_a8_260812_*`, and the usual results zip. `-DenoiseTargets smooth` can be added to
   train on denoised measured stains, or the scoring commands below take `--denoise-measured`.
   The ablation (light loss / FSC / SSC subsets) runs as part of it.

4. **Score against denoised measured stains** (what the abstract now quotes):
   ```
   python -m sperm_fluorescence accuracy runs\srv_a8_stems_260812 --cache data\server_cache\a8_roles_260812 --test 3 --title "A8 2026-08-12, held-out half" --sample 60000 --denoise-measured smooth --out figures\srv_a8_260812_accuracy_denoised
   python -m sperm_fluorescence masks runs\srv_a8_stems_260812 --cache data\server_cache\a8_roles_260812 --test 3 --limit 20000 --calib 400 --denoise-measured smooth
   python analysis\metrics_table.py runs\srv_a8_stems_260812 --accuracy figures\srv_a8_260812_accuracy_denoised\summary.json --denoise smooth --denoised-only --label "A8 2026-08-12"
   python -m sperm_fluorescence panel runs\srv_a8_stems_260812 --cache data\server_cache\a8_roles_260812 --test 3 --rows best:5 --main M --stained "LDHC,ACRV1" --size 56 --um-per-px 0.333 --approx-scale --range sample --denoise-measured smooth --marker-order ACRV1,TOMM20,LDHC --out figures\srv_a8_260812_panel.png
   ```

5. **Virtual stains, features, clustering** on the held-out half: `server_populations.ps1` is
   written for the July cache and run names, so run its stages by hand with the new names
   (the commands are the same ones it contains):
   ```
   python -m sperm_fluorescence predict runs\srv_a8_stems_260812 --cache data\server_cache\a8_roles_260812 --classes 3M --tta --out data\server_cache\a8_vstain_260812
   python -m sperm_fluorescence features data\server_cache\a8_vstain_260812 --out data\server_cache\a8_vstain_260812\features.csv
   python -m sperm_fluorescence populate data\server_cache\a8_vstain_260812\features.csv --set all --k 2 --no-gates --store data\server_cache\a8_vstain_260812 --gallery-n 8 --out runs\pop_srv_a8_260812_feat_k2
   python -m sperm_fluorescence populate data\server_cache\a8_vstain_260812\features.csv --set all --k 3 --no-gates --store data\server_cache\a8_vstain_260812 --gallery-n 8 --out runs\pop_srv_a8_260812_feat_k3
   python analysis\confusion_matrix.py runs\pop_srv_a8_260812_feat_k2 --names sperm leukocyte --out figures\srv_a8_260812_pop_feat_k2_confusion.png
   python analysis\cluster_grid.py runs\pop_srv_a8_260812_feat_k2 runs\pop_srv_a8_260812_feat_k3 --store data\server_cache\a8_vstain_260812 --views stains ssc --out figures\srv_a8_260812_pop_grid_k2_k3.png
   ```
   This is an ejaculate without added PBMCs and without a leukocyte marker, so k = 2 will not be
   sperm versus leukocyte: expect it to land on the tail-configuration split (straight versus
   looped) or on sperm versus round cells / debris, driven by light loss, scatter and the LDHC
   tail. Read the galleries before naming the clusters; the midpiece (TOMM20) adds a compartment
   the July A8 features never had, so the head / midpiece / tail geometry is richer here. The confusion matrix's `--names` must follow
   what the galleries show, by cluster id (`"0=..." "1=..."`).

## Before any of this: the CD45 / TOMM20 question on the July data

The July A8 panel is labelled CD45 on PE by the instrument and behaves as a leukocyte stain in
sixty thousand cells; the staining record is still being confirmed. This rerun does not depend
on it: the new panel's labels come from the new FCS files and the survey, and the 2026-08-12
marker is TOMM20 by the mentor's account. If the July channel also turns out to be TOMM20, the
July results are relabelled with `scripts/relabel_markers.py` and the July midpiece absence
becomes a finding to explain, not a label to hide.
